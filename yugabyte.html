YugabyteDB

Tablet Raft groups, leader distribution, and production behavior.

YugabyteDB uses Raft per tablet, which means the database runs many Raft groups in parallel.

Tablet Raft Groups

Each tablet has a leader and followers. Writes for a tablet are coordinated by that tablet's leader, not by one global database leader.

Leader Distribution

Balanced tablet leadership matters because leader-heavy nodes become write-coordination hotspots.

Frequent Elections

Check network loss, disk stalls, overloaded RPC threads, and CPU starvation.

Follower Catch-up

Lagging replicas catch up via log replay, snapshot, or remote-bootstrap style recovery depending on how far behind they are.

Tuning Areas

Heartbeat timing, election timeouts, placement policies, load balancing, WAL throughput, and compaction behavior matter most.
